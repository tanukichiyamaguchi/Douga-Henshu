# 映像処理テクニック（tools/vfx）

「AI動画の映像処理テクニック100選」（東大Codex研究所。4 分類 × 25 項目）の 100 項目を記録し、そのうち
**74 項目を、この環境（GPU なし・CPU 4 コア）で動くコマンドにした**。残りの 26 項目は作っていない
（2026-11-15、ユーザーの判断で 74 項目で完了）。開発の決まりは `tools/vfx/DEVELOPING.md`。
番号・分類・項目名は図表に合わせ、「何をする」と「頼み方の例」は図表の文を写さず Claude の言葉で書いた（公開リポジトリのため）。

## 使い方

```bash
cd tools
uv run python -m vfx list                  # 100 項目と状態
uv run python -m vfx list --cat 3          # 分類で絞る（1 動き / 2 画質 / 3 切り抜き・合成 / 4 自動で見つける）
uv run python -m vfx info 56               # 1 項目の中身・実測・限界・試した素材と、引数の説明
uv run python -m vfx matte 入力.mp4         # 名前で実行
uv run python -m vfx 56 入力.mp4            # 番号でも実行できる
```

- 入力は動画か画像（透過つき WebM も読める）。
- 出力先は `-o`。省略すると `out/vfx/<元の名前>-<コマンド名>.<拡張子>`（Git に入らない）。多くのコマンドが、処理した
  映像・画像のほかに、数値の JSON（時刻は元の動画の中の秒）と、確かめる用の画像（前後の比較・コマを並べた物）を書く。
  最後に `保存: <パス>` が出る。
- 多くのコマンドにある引数: `--start`・`--duration`・`--max-frames`（範囲）、`--max-side`（処理する時の長辺の上限。
  速くしたい時）。あるかどうかは `--help` で確かめる。
- 映像の書き出しは MP4（H.264。6 コマごとのキーフレームで HyperFrames にそのまま置ける。BT.709 の色の印つき）。
  透過が要る物は WebM（VP9 の透過）。元に音声があれば残す。

## 進め方（必ず守る）

1. `info <番号>` で「限界・注意」を読み、合うコマンドと引数を選ぶ。素材が条件に合わない時（例: 固定カメラ用の処理に
   手持ちの映像）は、そのことをユーザーに伝える。
2. 最初は短い範囲・小さい大きさで試す（例: `--max-frames 24 --max-side 540`）。AI のモデルを使う物は 1 コマ数秒かかる。
3. 確かめる用の画像を Read で開き、**自分の目で見る**。JSON の数値も見る。動画の素材にするなら、要所（カットの前後など）の
   連続したコマを並べて見る。
4. 報告では、使ったコマンドと設定、出た数値、目で確かめたこと・確かめていないことを伝える。状態が ○・△ の項目は、
   その限界も伝える。

## HyperFrames の作品で使う時

- vfx は、作品に置く**前の素材そのもの**を作り直す道具。出力を `work/<作品>/assets/` に置いて使う。
- 作品の中で映像に色調・粒子・ぼかし・周辺減光をかけるだけなら、HyperFrames の決まり（CSS の filter を使わず
  `npx hyperframes media-treatment`）に従う。vfx を使うのは、それでは足りない処理（手ぶれ補正・ノイズ除去・切り抜き・
  物を消す・超解像・補間など）。
- 人物の切り抜きは、これまで `npx hyperframes remove-background` を使ってきた（CLAUDE.md）。vfx の `matte`（56）は
  髪の毛先まで残す別の方法。2 つを同じ素材で比べたことはない。
- `track`（2）は HyperFrames 用の `.js` も書く。作品の `assets/` に置いて `<script src>` で読み、
  `window.vfxFollow(tl, 要素, window.__vfxTracks["名前"], {start, mediaStart, anchor, dx, dy})` に、映像の `data-start`・
  `data-media-start` を渡すと、文字や絵が物に付いて動く。既定は 1080×1920 の全面に cover で置く前提（`--comp-size`・
  `--fps` で変える）。
- `planar-track`（6）・`mesh-warp`（25）は、手前を横切る物で隠れることを扱わない（切り抜きと組み合わせる）。
- `inverse-tonemap`（32）の HDR の出力は納品用（HyperFrames は SDR として描く）。HDR の素材を作品に入れる時は
  `tonemap`（33）で SDR にする。
- `deband`（45）の後に書き出し直すと（HyperFrames の書き出しも含む）、縞が戻ることがある。
- 色（2026-11-15 実測）: vfx の MP4 を HyperFrames に置いて書き出すと、灰色の段と色見本は元の値から ±2 以内。
  透過つき WebM は、写真の部分が平均 1 段暗く描かれた（HyperFrames が WebM を読む時の変換による）。

## 時間・容量・メモリ

- GPU なし。ffmpeg・OpenCV だけで動く物は 1 コマ 0.1 秒未満が多く、AI のモデルを使う物は 1 コマ 1〜十数秒かかる
  （CPU の混み具合で数倍変わる）。項目ごとの目安は `info` の「実測」。
- モデルは、初めて使う時に取得する（セッションごと）。単体のファイルは `~/.cache/douga-vfx/`（全部取ると約 2.3GB）、
  Hugging Face のモデルは `~/.cache/huggingface/`（作った時は、文字起こしのモデルも含めて約 7.6GB。例: Florence-2 large
  1.55GB、X-CLIP 786MB）。
- ディスクの枠は限られている（`df` の空きは当てにならない。作った時にも一杯になった）。大きな中間ファイルは消す。
- `matte --model birefnet`（人以外も切り抜く）はメモリを約 7GB 使う。重い処理を並べて走らせない。

## ライセンスと扱い

- 使うモデルは、商用で使えるライセンス（Apache-2.0・MIT・BSD など）の物だけ。モデル名とライセンスは各項目の「中身」に
  ある。学習に使われたデータの利用条件は、各配布元による（torchvision も、学習データの条件は使う人が確かめるよう
  注意書きしている）。
- 実在の人物の顔を加工しない。広告に使う実在のスタッフの写真は、CLAUDE.md の「広告動画の場合」のとおり、本人の了承を
  ユーザーに確かめ、加工せずそのまま使う（加工するのは、本人の了承があり、ユーザーが頼んだ時だけ）。人を見分ける処理
  （`reid`・`multi-track` など）を、実在の人を特定する目的で使わない。実在の人の名前は、ファイル名も含めてリポジトリに書かない。
- 描き足し・消去（`inpaint`・`outpaint`・`sky-replace` など）で作った部分は、実際の場所や物とは違う。広告では、店内の様子や
  施術の結果など、事実を示す場面に使わない。注意書きで補うことはしない（広告には注意書きを入れない。CLAUDE.md）。
