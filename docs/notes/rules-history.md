### 手順

1. **依頼の整理**: 目的・見る人・伝えたいことを 1 行にまとめる。店名・商品名・日付など、内容に欠かせない
   情報が無い時だけ、一問一答で質問する（形・長さ・演出は既定値で進め、質問しない。トンマナは下の
   「トンマナの決め方」に従う）。作り始める前に、下の「毎回守ること」と「指示の記録と引き継ぎ」を読む。
   前に作ったことのある依頼主なら `docs/clients/` の記録も先に読み、価格・掲載期間・比較の数字など変わりやすい所を、使う前に
   一問一答で確かめる。スタッフの写真を使う時は、本人の了承も確かめる（下の「広告動画の場合」）。
2. **台本と絵コンテ**: 話のまとまり（場面）は 3〜6 つ。その中を**カット（同じ絵が続く長さ）**に割り、カットごとに
   「秒数・画面の文字・ナレーション文・素材（生成映像／生成画像／文字だけ）」を表にする。素材の列は、どのカットも映像か写真にする
   （2026-11-16。文字と、コードで描いた図形だけのカットを作らない。下の「毎回守ること」）。画面の文字の列には、置く位置
   （下の「テロップの置き方と見た目」の型）も書き、同じ位置を続けない（2026-11-18）。カットの長さ・話す速さ・文の間は、
   下の「毎回守ること」のテンポの目安に合わせ、表の下に「カットの数・平均の長さ・いちばん長いカット・文の間」を
   書く（2026-11-16 のテンポの指示。それまでは場面ごとの表だけで、1 つの絵が 3 秒前後続いていた）。
   依頼に強みが多く並んでいる時は、入れる訴求を 3 つまでに絞り、表の上に「入れる訴求／外す訴求」を書く（2026-11-17。下の
   「毎回守ること」の「伝える事と画面の文字は、絞る」）。
   費用の見積もりも出す（下の目安）。10 ドル以内なら次へ進む。
3. **素材の生成**: 画像 → 映像 → BGM → ナレーションの順。生成物は `work/<日付-名前>/assets/` に置く。
   作り直しは原因を言える失敗（文字が入った、構図が違う等）の時だけ、1 回まで。映像の取得失敗は
   `gen_video.py --task-id` で取り直す（無料）。
4. **ナレーションの確認**: `transcribe.py` で文字起こしし、台本どおりに読めているか確認する。
   字幕のタイミングもこの結果を使う。声は加工しないで使い（上の表「声の質」）、音量や間を調えた時は、`voice_check.py` の
   `--before`・`--after` で、声が変わっていないことを測る（下の「テンポと声の指摘で測ったこと」）。
5. **組み立て**: `work/<日付-名前>/` に `npx hyperframes init <フォルダ> --example=blank --non-interactive
   --skip-skills --resolution portrait` で作品を作り、素材・テロップ・字幕・音声を配置する。
6. **自分で確認**: `npm run check` を合格させ、`npx hyperframes snapshot` で主要な場面を画像で見て直す。
   書き出した MP4 は `ffprobe` で長さ・解像度・音声の有無を確認し、`transcribe.py` で音声も確認する。
   場面の切り替わり・文字と顔の重なり・スマホの実寸での読みやすさも、書き出した MP4 のコマで確かめる
   （下の「毎回守ること」）。テロップの位置と見た目は、下の「テロップの置き方と見た目」の「確かめる所」で確かめる（2026-11-18）。
   テンポの数字（大きな動きの回数・動いている時間の割合・いちばん長いカット・文の間）も、
   書き出した MP4 を `tempo_check.py` で測る。
7. **お届けと報告**: 完成品を送り、「使った素材と費用の見積もり」「確認したこと」「確認できなかったこと」
   （例: 声の自然さは耳で確認していない）を短く報告する。テンポの数字と、使った声の名前・声にかけた加工も書く。

### トンマナの決め方（2026-11-15 ユーザー決定）
