# 2026-11-18 の調査: トークンと時間が増え、仕上がりが悪くなった理由

ユーザーの言葉: 「このレポジトリにおいて、直近4動画程がこれまでよりかなりのトークンを食うようになった。そして時間も初期より
大幅にかかる。それなのに、仕上がりが悪くなっている。これの理由を特定し、除いて欲しい」

調べた物: 動画を作った各セッションの使用量の記録（セッションの情報と、依頼ごとの結果の記録）、CLAUDE.md の変更履歴（git）、
このセッションでの実測、Claude API の公式資料（Claude Code に入っている `claude-api` スキル。モデルの移行の手引き）、
Claude Code 本体（2.1.326）の設定の説明。

## 原因

1. **会話が長くなりすぎた。** 1 つのセッションで何本も作り、直しを重ねたため、1 回の要求が 50〜78 万トークンになっていた。
2. **CLAUDE.md が 4 日で 50 倍になった。** 毎回の要求とサブエージェントに、約 12 万トークンが丸ごと入っていた。
3. **複数のエージェントによる検査と、重い設定。** 11-17 から「納品の前に 9〜10 人の検査のワークフローを走らせる」が
   決まりになっていた（Claude が書いた決まり）。動画のセッションは Fable 5.2・effort xhigh で、1 つは ultracode がオン。
   公式資料は、Fable 5.2 は high から始め、xhigh は効果を確かめられた所だけにするよう勧めている（トークンが大きく増えるため）。
4. **仕上がりが悪くなった理由。** 公式資料によると、Fable 5.2 は指示ファイルに積み上がった注意書きに強く従う。理由が
   なくなった注意書きは消し、詰まったら「メモを削って始め直す」ことを勧めている（Fable 5.1 の節には、細かすぎる指示は
   仕上がりを下げる、ともある）。CLAUDE.md は、決まりが行ったり来たりし（文字を Claude が組まない → 撤回、話す速さ 1.25 倍 →
   速さの加工は使わない、作りのお手本の決まりが 1 日で 3 通り）、1 回の指摘から Claude が広げた解釈が次の作品を縛っていた
   （動きの数字の目安のために飾りを足して「ダサい・AI っぽい」、最後も 2 秒ごとに切り替えて「ガチャガチャ」、KATE のリールの
   作りを医療広告に当てはめてピンク）。確かめる決まりが増え、1 回の依頼の要求の回数（＝時間）も増えた。

## ユーザーが決めたこと（2026-11-18。一問一答の答え）

- 会話の長さ: **新しい動画は新しいセッションで始める。自動の要約は約 30 万トークンで始める**（「新セッション＋要約30万」）。
- 検査のワークフロー: **頼まれた時だけ使う**。納品前の確認は Claude 自身が行う。
- Claude の解釈: **決まりから外して、参考資料（docs/）へ移す**。決まりに残すのは、ユーザーが決めたことと技術的な落とし穴だけ。
- 手間（effort）の上限: **今のまま**（リポジトリの設定では変えない）。

## 直したこと

- CLAUDE.md を、いま有効な決まりだけに作り替えた。元の文は消さずに、`docs/notes/` の資料へそのまま移した
  （決まりの経緯 `rules-history.md`、医療広告 `medical-ads.md`、テロップ `telop.md`、測定 `measurements.md`、
  作品ごとの記録 `production-log.md`、環境と道具 `environment-and-tools.md`）。移した後、元の行が全部あることを機械で確かめた。
- `.claude/settings.json` の `env` に `CLAUDE_CODE_AUTO_COMPACT_WINDOW=300000` を足した（Claude Code 2.1.326 では、この
  環境変数がほかの設定より先に効く。要約は、30 万から要約を書くための余白を引いた所で始まる）。
- 依頼主の記録（`docs/clients/kate-stage-lash-kamata.md`）の「これまでの納品」を、別の資料
  （`docs/clients/kate-stage-lash-kamata-history.md`）にそのまま分けた。元の行が全部あることを機械で確かめた。
- 新しい CLAUDE.md に残した文を、元の文と 1 つずつ突き合わせた。元の文で「Claude の解釈・判断・反省」と書かれていた物のうち、
  作りを縛る物（声の大きさの 3dB の目安、テロップの「字 1 字ぶん空ける」「飛んでくる途中ははみ出してよい」、「1 場面 1 メッセージ・
  出しっぱなしの札は最小限」、訴求は 3 つまで、「コードで作るのは文字・札・線・矢印・色の幕まで」、効果音の「−21 dBFS 以下」、
  医療広告の言い方の扱い）は外した（資料には残っている）。作りを縛らない手順と、規制・審査の落とし穴（金額の確かめ方・偽の
  トグル・医療広告の要点など）は、理由か「Claude の判断」を書き添えて残した。
- 「作業の進め方」の節は、ユーザーが決めた 3 項目と、この調査から Claude が足したやり方（`NOTES.md`・画像を見る量・見本で方向を
  確かめる・直しの受け取り方・数字の扱い）を分けて書き、後者には「ユーザーの決定ではない」と書いた。CLAUDE.md の 2 万字の上限も、
  Claude が決めた物（ユーザーの決定ではない）。

## 作り替えた後に測ったこと（2026-11-18）

- 何もしない確認役 1 体（前と同じ指示・同じ種類）: **19.3 万 → 9.0 万トークン**（実測。192,586 → 89,865）。確認役には新しい
  CLAUDE.md が見え、移した見出しは見えていなかった（確認役の答え）。
- 自動の要約: この調査のセッションで、設定を書いた直後に、**58.3 万トークンの所で自動の要約が起きた**（セッションの記録の
  `compact_boundary`。trigger は auto、preTokens 582,651 → postTokens 20,318、かかった時間 80 秒）。前の基準（約 90 万）では起きない
  大きさなので、設定が効いている。このセッションのコマンドの環境にも `CLAUDE_CODE_AUTO_COMPACT_WINDOW=300000` が届いていた。
  Claude Code 2.1.326 の本体の中にある「リポジトリの設定ファイルの env から外す名前」の一覧（約 200 個）に、この名前は無かった。
- 新しいセッションの最初の要求は、計算で約 10 万トークンの見込み（前は 20.3 万から、確認役で減った約 10.3 万を引いた。測っていない）。
- 要約にも時間と費用がかかる（今回は 1 回 80 秒、要約の前の会話を 1 回読む）。Claude Code 本体の設定の説明にも「既定（auto）を
  上書きすると、長いセッションを再開する時などに、トークンが増えることがある」とある。会話が長いほど要約の回数が増えるので、
  新しい動画は新しいセッションで始める決まりと合わせて使う（Claude の解釈）。

## 確かめられなかったこと

- 初期（2026-11-14）の動画の、依頼ごとの使用量と時間。記録を遡るのに大量の読み込みが要るため、取り出していない。
- 2 つのセッションで、セッションの情報の合計と、作業の記録側の累計の金額が食い違っていた（どちらが正しいかは分からない）。
- インプラントのセッションの、メインの会話の外で動いた要求（検査の担当や会話の要約など）の内訳。
- 新しいセッションの最初の要求の大きさ（計算の見込みだけ）。
- 30 万で要約した時に、制作の細部が抜けて仕上がりに響くか（`NOTES.md` で補う。次の作品で確かめる）。
- 作り替えた後の仕上がりの良し悪し（次の作品への感想で確かめる）。
